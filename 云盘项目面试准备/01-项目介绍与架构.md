# 项目介绍与架构

## 一句话介绍

这是一个基于 Qt、C/FastCGI、Nginx、MySQL和 FastDFS实现的云盘系统原型，支持用户鉴权和文件上传、列表、下载、删除、限时分享，并通过 Docker完成一键部署。

## 30秒版本

我参与的是一个 Qt加 C/FastCGI的云盘项目。Qt和 Web客户端通过 HTTP访问 Nginx，Nginx把请求转发给7个 FastCGI接口；MySQL保存用户、Token和文件元数据，文件优先写入 FastDFS，失败时回退到本地目录。我重点修复了 Token安全、文件越权、multipart二进制解析、MD5校验、分享链接以及 Docker部署问题，并完成了功能回归和本机轻量压测。

## 1分钟版本

我做的是一个基于 Qt和 C语言 FastCGI的云盘系统原型。客户端包括 Qt桌面端和 Web端，后端由 Nginx接收 HTTP请求，再转发给注册、登录、上传、下载、文件列表、删除和分享7个 FastCGI程序。MySQL保存用户、Token和文件元数据，文件优先存入 FastDFS，失败时可以回退到本地持久化目录，整个环境通过 Docker Compose部署。

我重点处理了三类问题。第一是鉴权安全：文件接口不信任客户端提交的用户 ID，而是通过 `X-Auth-Token`反查真实用户，并校验文件所有权；同时把可预测的 `rand()` Token替换成 OpenSSL安全随机数。第二是文件链路：修复 multipart boundary、二进制解析、MD5一致性校验，以及上传、下载、删除和分享的异常处理。第三是客户端和部署：修复 Qt协议字段、上传鉴权、分享链接显示，以及 Docker中的数据卷、FastDFS地址和多工作进程配置。

项目完成过注册登录、二进制上传、下载一致性、跨用户隔离、分享过期和删除等回归测试。不过当前仍是本地演示架构，密码哈希、HTTPS、Token生命周期和服务拆分仍需继续完善。

## 3分钟展开框架

### 1. 项目来源

如果是二次开发，可以这样说：

> 项目最初是教学样例，已有基本页面和接口，但上传格式、鉴权、二进制处理、存储部署和客户端协议存在不完整之处。我主要负责对现有系统进行后端加固、Qt适配、容器化部署和完整链路测试。

### 2. 请求链路

```text
Qt / Web
   ↓ HTTP，X-Auth-Token
127.0.0.1:8080
   ↓ Docker 8080:80
Nginx
   ↓ 按URL转发
7个FastCGI程序
   ├─ MySQL：用户、Token、元数据
   ├─ FastDFS：主要文件存储
   └─ local：失败回退存储
```

### 3. 登录鉴权

登录接口校验用户名和密码，使用 OpenSSL `RAND_bytes()`生成 Token并保存到 MySQL。客户端后续通过 `X-Auth-Token`携带凭证，服务端根据 Token得到用户 ID。文件查询条件同时包含文件 ID和用户 ID，以避免水平越权。

### 4. 上传链路

Qt通过 `QHttpMultiPart`发送 `multipart/form-data`。服务端从 `CONTENT_TYPE`提取 boundary，按字节长度解析二进制数据，重新计算 MD5，并与客户端值比较。文件优先上传 FastDFS；失败时写入本地持久化目录；最后把文件名、大小、MD5、存储类型和状态写入 MySQL。

### 5. 删除和分享

删除先把状态从 `active`更新为 `deleting`，再删除物理文件，最终记录 `deleted`或 `delete_failed`。分享前验证文件归属，生成随机分享 Token并保存过期时间；匿名下载只能使用有效且未过期的分享 Token。

### 6. 测试与边界

历史回归覆盖23项，包含异常密码、无效 Token、二进制上传、MD5错误、跨用户访问、分享过期和删除清理。本机短时轻量压测中，文件列表500请求、并发20时全部成功，吞吐约1107 req/s、P95约28.71 ms。该结果不能代表生产容量，也不能自动证明请求一定走 FastDFS，因为系统有本地回退路径。

## 技术栈

| 层次 | 技术 | 项目作用 |
|---|---|---|
| 桌面客户端 | Qt 6、C++、QNetworkAccessManager | 登录、上传、列表、下载、删除、分享 |
| Web客户端 | HTML、CSS、JavaScript | 浏览器端完整功能 |
| 接入层 | Nginx | 静态页面、HTTP接入、FastCGI路由 |
| 业务层 | C、FastCGI | 7个业务接口 |
| 数据层 | MySQL C API | 用户、Token和文件元数据 |
| 存储层 | FastDFS、本地目录 | 文件内容存储与回退 |
| 安全/摘要 | OpenSSL RAND、MD5 | Token随机数、文件校验；密码MD5为遗留问题 |
| 部署 | Docker、Compose | 镜像构建、端口映射和数据卷 |

## 不应声称的内容

- 不说“Token存在 Redis”，实际在 MySQL。
- 不说“密码使用 MD5很安全”，它是遗留风险。
- 不说“高可用分布式集群”，当前是单节点演示部署。
- 不说“支持10GB文件”，后端请求体限制为10 MiB。
- 不说“FastDFS已完整压测”，除非上传结果明确显示使用 `fastdfs`。
- 不用本机短时 QPS推导生产容量。
