# MySQL、Redis与Docker八股

## MySQL

### 1. 为什么MySQL索引通常使用B+树？

B+树分支多、高度低，减少磁盘I/O；数据主要在叶子节点，叶子节点有序连接，既适合点查也适合范围查询。

### 2. 聚簇索引和二级索引是什么？

InnoDB聚簇索引叶子节点保存完整行，通常按主键组织；二级索引叶子节点保存索引列和主键，再根据主键回表读取其他列。

### 3. 什么是联合索引最左前缀？

联合索引按列顺序排序，查询通常需要从最左列开始连续使用，才能充分利用索引。例如 `(user_id,status)`适合按用户和状态查询。

### 4. 项目可能需要哪些索引？

`users.username`已有唯一约束；`users.token`适合唯一索引；`files(user_id,status)`适合文件列表；`files.share_token`适合唯一或普通索引，提升分享下载查询。

### 5. 事务ACID是什么？

原子性保证事务内操作全部成功或全部回滚；一致性保证约束不被破坏；隔离性控制并发事务相互影响；持久性保证提交结果在故障后仍能恢复。

### 6. MySQL隔离级别有哪些？

读未提交、读已提交、可重复读、串行化。InnoDB默认通常是可重复读，并通过 MVCC和锁减少并发异常。

### 7. 什么是脏读、不可重复读和幻读？

脏读是读到未提交数据；不可重复读是同一行两次读取结果不同；幻读是同一范围查询出现新增或消失的行。

### 8. MVCC是什么？

多版本并发控制通过记录版本和 Read View，让读操作看到合适版本，减少读写互相阻塞。它主要用于普通一致性读，当前读仍可能加锁。

### 9. 乐观锁和悲观锁有什么区别？

悲观锁先加锁再修改，适合冲突较多；乐观锁通过版本号或状态条件更新，冲突时失败重试。项目删除的 `WHERE status='active'`属于类似乐观状态抢占。

### 10. 如何防止SQL注入？

首选参数化预处理语句；同时做类型和范围校验、最小权限、固定字符集并避免暴露数据库错误。转义只能作为补充。

### 11. 什么是连接池？

预先创建并复用一定数量数据库连接，避免每次请求建立TCP、认证和初始化连接。连接池需要最大连接数、超时、健康检查和归还机制。当前C接口主要按请求创建连接，没有完整连接池。

### 12. 如何分析慢SQL？

先看慢查询日志和真实参数，再用 `EXPLAIN`检查访问类型、索引、扫描行数、临时表和排序；随后优化索引、查询结构或数据模型，并重新测量。

## Redis

### 13. Redis为什么快？

主要数据在内存中；核心命令执行路径短；事件循环和I/O多路复用减少线程调度；数据结构经过专门优化。不能简单归因于“单线程”。

### 14. Redis常见数据类型有哪些？

String适合缓存和计数；Hash适合对象字段；List适合队列；Set适合去重和集合运算；Sorted Set适合排行榜和延迟任务。

### 15. RDB和AOF有什么区别？

RDB定期生成快照，文件紧凑、恢复快但可能丢失最近数据；AOF记录写命令，数据更完整但文件更大。Redis可组合使用。

### 16. 缓存穿透、击穿和雪崩是什么？

穿透是持续查询不存在数据，可用空值缓存或布隆过滤器；击穿是热点键失效，大量请求同时打数据库，可用互斥重建或逻辑过期；雪崩是大量键同时失效或Redis故障，可分散过期时间、限流和高可用。

### 17. Token放Redis有什么优点？

查询快、天然 TTL、易于主动删除和共享会话。但需要考虑 Redis故障、数据持久化、与 MySQL的一致性以及缓存不可用时的降级策略。

### 18. 当前项目使用Redis了吗？

Redis服务会启动，但当前代码没有把 Token或业务数据放入 Redis。面试时应把 Redis会话缓存描述为优化方案，而不是已实现功能。

## Docker

### 19. 镜像和容器有什么区别？

镜像是只读模板，包含程序和依赖；容器是镜像的运行实例，具有可写层、进程、网络和资源限制。

### 20. Dockerfile每条指令为什么形成层？

分层便于缓存和复用。某一层及之前内容不变时可以使用缓存；频繁变化的源码复制通常放在依赖安装之后，以减少重复构建。

### 21. `CMD`和 `ENTRYPOINT`有什么区别？

`ENTRYPOINT`通常定义固定执行程序；`CMD`提供默认命令或默认参数，运行容器时更容易覆盖。JSON数组形式可避免额外Shell解析。

### 22. 数据卷有什么作用？

把数据从容器可写层独立出来，便于持久化、备份和在容器重建后复用。项目为 MySQL、本地上传目录和 FastDFS Storage配置了命名卷。

### 23. 容器网络如何理解？

容器有自己的网络命名空间和内部IP。同一 Compose网络中的多容器通常用服务名通信；宿主机通过端口映射访问容器服务。

### 24. 为什么单容器运行多个服务不理想？

生命周期、日志、健康检查和资源隔离耦合；一个服务失败后容器未必退出；难以独立扩缩容和升级。课程演示可以简化部署，生产应按服务拆分。

### 25. Docker健康检查有什么价值？

容器进程存在不代表业务可用。健康检查可以真实请求接口或检测依赖，区分 `running`和 `healthy`，供编排系统重启或停止流量。

### 26. 为什么 `tail -f /dev/null`不是好的PID 1？

容器存活只取决于 tail，业务进程全部崩溃后仍显示运行；同时信号转发和子进程回收不完善。应让主服务前台运行，或使用合适的进程管理器并增加健康检查。
